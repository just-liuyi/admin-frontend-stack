# 系统设置页

设置项会随业务不断增加，所以设置页**按分类拆开**：顶部是分类页签，下面一次只显示一个分类的表单，**每个分类单独保存**。

效果图：`assets/previews/settings-desktop.jpg`。

最后核实：2026-11-17（React 19.3、react-hook-form 7、zod 4、shadcn CLI 4.22、radix-nova）。
验证方式：`assets/settings/` 的 4 个文件放进按 `quickstart.md` 从零搭建的空项目里，`tsc -b`、`vite build`、依赖严格检查通过；浏览器走查了下文「交付检查」的全部项目。

## 直接用现成代码

| 文件 | 放到 | 作用 |
|---|---|---|
| `index.tsx` | `src/pages/settings/index.tsx` | 页面：标题、分类页签、未保存修改的确认弹窗 |
| `sections.tsx` | `src/pages/settings/` | 分类清单 + 每个分类的字段和校验规则 |
| `settings-form.tsx` | `src/pages/settings/` | 分类表单外壳（读取、保存、取消、未保存提示）和字段组件 |

在 `src/config/routes.tsx` 里把 `/settings` 的占位页换成 `import SettingsPage from "@/pages/settings"`。

## 布局

```
系统设置
按分类管理系统配置，每个分类单独保存
基本信息  订单规则  [账号安全]  消息通知  支付配置  文件存储  数据备份      ← 下划线页签，带图标
┌────────────────────────────────────────────────────────────────┐
│ 账号安全                                                         │ ← 分类标题 + 一句说明
│ 注册、密码与登录相关的安全策略                                     │
├────────────────────────────────────────────────────────────────┤
│ 密码最少位数        连续登录失败锁定（次）   无操作自动退出（分钟）   │ ← 字段网格
│ [ 8          ]     [ 5           ]       [ 120          ]       │
├────────────────────────────────────────────────────────────────┤
│ 有未保存的修改                                    [取消] [保存]   │
└────────────────────────────────────────────────────────────────┘
```

- **卡片占满内容区宽度**，不要给表单加 `max-w-3xl` 之类的限宽（宽屏上右边会空一大块）。
- 分类页签用下划线样式（`TabsList variant="line"`），选中项主色文字 + 主色下划线；手机上页签横向滑动。
- 页签适合 **7 个以内**的分类。分类多到一排放不下时，改成左侧竖排分类导航（大屏左侧 13rem 竖排、小屏横排滑动），表单部分不用改。

## 字段排版

- 字段放进 `FieldGrid`：手机一列，`md` 两列，`2xl` 三列。输入框不会被拉得过长，宽屏也不空。
- 长文本（`TextareaField`）独占一整行。
- **所有字段同一种结构：标题在上、控件在下、说明在最下。** 开关也一样：标题在上，开关那一行与输入框同高（radix-nova 的 Input 是 `h-8`），旁边写"已开启 / 已关闭"，说明在下面。这样同一行里的输入框、下拉框、开关，标题、控件、说明全部对齐。
- 不要把开关做成带边框的卡片和输入框混排，也不要把开关放到行的最右端、离文字很远。

## 行为

- **每个分类单独保存**：保存时只提交本分类的字段（`saveSettings(Partial<Settings>)`），成功提示"「分类名」已保存"。
- 没有修改时"取消""保存"不可点；有修改时左下角显示"有未保存的修改"。"取消"恢复成上次保存的值。
- **切换分类时如果有未保存的修改，弹窗确认**："继续编辑"留在原分类，修改保留；"放弃修改"切过去，修改丢弃。
- 当前分类写在地址里（`?tab=account`，第一个分类不写参数）：刷新、分享链接、在顶部多页签之间来回切换后，都停在原来的分类。
- 校验用 Zod，错误用中文显示在字段下方；`<form noValidate>`。
- 加载中显示骨架，出错显示"重试"。

## 新增一个分类 / 一个设置项

新增设置项：
1. `settings-api.ts`：在 `Settings` 类型和默认值里加字段（接后端后由接口返回）。
2. `sections.tsx`：在对应分类的 `schema`、`pick` 和 JSX 里各加一处。

新增分类：在 `sections.tsx` 里写一个 `XxxSection` 组件（照抄已有分类的写法），再在 `settingCategories` 清单里加一行（`id`、`label`、Lucide 图标、组件）。页签和地址参数自动生效。

## 已踩过的坑

1. **表单限宽，宽屏右边空一大块。** 卡片占满宽度，用字段网格控制输入框宽度，而不是限制整个表单的宽度。
2. **开关卡片和输入框混排对不齐。** 带边框的开关卡片比输入框高、顶部也不对齐，一行里三种边框，整体不协调。开关改成和输入框同一种结构（见「字段排版」）。控件行高度要等于当前风格 Input 的实际高度，换 shadcn 风格时跟着改。
3. **深色模式下刚点过的页签变白字。** 见 `patterns.md` 的 Tabs 选中色一条，浅色、深色都要写"选中时悬停也保持主色"。
4. **竖排分类导航在手机上把表单撑出屏幕。** 网格子项默认不会比内容更窄，横排的导航按钮会把整列撑宽；导航元素要加 `min-w-0`（见 `patterns.md`）。检查时要量表单右边缘有没有超出屏幕，只看页面有没有横向滚动条会漏掉（外层把超出部分藏起来了）。

## 交付检查

- 默认显示第一个分类；点页签切换，地址带上 `?tab=…`；刷新后仍在原分类
- 修改后出现"有未保存的修改"，保存按钮可用；切换分类时弹出确认
- "继续编辑"：留在原分类、修改还在；"放弃修改"：切过去，修改没有被保存
- 校验：超出范围显示中文错误
- 保存成功：提示"「分类名」已保存"、未保存提示消失；切走再切回，保存的值还在；保存后切换不再弹确认
- 1440 和 1920 宽度下，每个分类同一行字段的标题顶部、控件中线、控件高度全部对齐
- 手机：没有横向滚动，表单完整显示在屏幕内
- 深色模式：点过的页签在鼠标悬停时仍是主色
- 控制台没有运行时错误
