# 多页签（标签页）模式

打开过的页面在顶栏下方排成一排页签，可来回切换、关闭；切走再切回时页面状态（筛选、分页、勾选、表单输入）保留。

最后核实：2026-10-23（React 19.3.1、react-router 8.5、zustand 5.0、shadcn CLI 4.22.1 的 `context-menu` / `dropdown-menu`）。
验证方式：`assets/tabs/` 的代码在真实工程里通过 `tsc -b` 和 `vite build`，并用无头浏览器（Edge）走查了下文「交付检查」的 25 项行为，导航外壳原有的 24 项检查同时全部通过。

效果图：`assets/previews/shell-desktop.jpg`（顶栏下方的页签栏）。

## 什么时候开启

**默认开启，是导航外壳的标准功能。** 只有以下情况才不做页签：
- 用户明确说不要页签、只要单页面切换；
- 原型模式下用户只要单个页面的视觉稿。

不做页签时，用 `assets/navigation/app-shell-no-tabs.tsx`（单页面外壳，内容区用 `<Outlet />`，路由写在 `App.tsx` 的 `<Routes>` 里）。

React 版本低于 19.2（没有 `<Activity>`）时：页签栏照做，但不做状态保留，并在交付说明里写明。

原型模式（单文件 HTML）同样要有页签栏，至少能切换、点 × 关闭、右键出现同一组关闭操作。

## 直接用现成代码

| 文件 | 放到 | 作用 |
|---|---|---|
| `tabs.ts` | `src/stores/tabs.ts` | 页签状态与全部关闭操作（Zustand，存 sessionStorage） |
| `tab-bar.tsx` | `src/components/` | 页签栏：点击切换、× 关闭、中键关闭、右键菜单、右侧 ⌄ 菜单 |
| `tab-views.tsx` | `src/components/` | 页面容器：每个页签一份页面，用 `<Activity>` 隐藏非当前页签 |
| `routes.tsx` | `src/config/routes.tsx` | 页面路由表**模板**：自带占位页和 404 页，开箱能编译；把占位页换成真实页面，地址与 `nav.ts` 对应 |

外壳本身是 `assets/navigation/app-shell.tsx`（默认就带页签栏）。还需要：`npx shadcn@latest add context-menu`，以及 `@tanstack/react-query`（页签"刷新"会让当前页的数据重新请求，入口要有 `QueryClientProvider`，直接用 `assets/shared/main.tsx`）。
`App.tsx` 只渲染 `<AppShell />`，不再写 `<Routes>`；页面路由统一写在 `routes.tsx`。

## 布局与外观

```
┌──────────────┬──────────────────────────────────────────────┐
│ [N] Nova [◧] │ 用户管理 > 用户列表           🔍  🔔  (AD)   │ ← 顶栏 56px
├──────────────┼──────────────────────────────────────────────┤
│              │ 📌仪表盘  [用户列表 ×]  角色权限  订单管理    ⌄ │ ← 页签栏 40px，和顶栏一起吸顶
│              ├──────────────────────────────────────────────┤
│              │  页面内容                                     │
```

- 页签是小胶囊：当前页签用主色浅底 + 主色字（与侧边栏选中样式一致），其余为次要文字色，悬停灰底。
- 当前页签常显 ×，其他页签悬停时才显示 ×；固定页签（仪表盘）带图钉图标、没有 ×。
- 页签多了横向滚动（隐藏滚动条），当前页签自动滚到可见处。
- **只在电脑上显示**。手机屏幕放不下，切换页面靠侧边栏抽屉。

## 行为规则

| 操作 | 结果 |
|---|---|
| 从侧边栏、链接或地址栏进入菜单里的页面 | 没有对应页签就加在最后；已有就切过去（一个页面只有一个页签，按 pathname 区分） |
| 菜单外的地址（404 等） | 正常显示，不进页签 |
| 点 × / 鼠标中键 | 关闭该页签；关掉的是当前页签时跳到右边的页签，右边没有就去左边 |
| 右键页签 → 刷新 | 重新挂载该页面并重新请求数据；筛选条件（在地址里）保留，勾选等临时状态清空 |
| 右键 → 关闭 / 关闭左侧 / 关闭右侧 / 关闭其他 | 以**右键的那个页签**为基准；当前页签被关掉时跳到右键的页签（与浏览器、VS Code 一致） |
| 关闭全部 | 只剩固定页签，跳回首页 |
| 右侧 ⌄ 按钮 | 同一组操作，以当前页签为基准（触屏设备没有右键，必须有这个入口） |
| 没有可关闭对象的操作 | 菜单项置灰（如固定页签的"关闭"、最左页签的"关闭左侧"） |
| 浏览器刷新 | 页签还在（sessionStorage）；新开浏览器窗口从只有首页开始 |
| 页签超过 10 个 | 自动关掉最左边的可关闭页签（首页和刚打开的页签不会被关）。上限 10 个是确定的规范，不要改 |

- 固定页签只有首页一个，永远在最左，不能关闭，保证页签栏不会被关空。
- 页签标题来自菜单配置（`findNavTrail`），不要在页面里各自设置标题。
- 页签状态是客户端 UI 状态，放 Zustand；页面的服务端数据仍归 TanStack Query。

## 状态保留（keep-alive）怎么做的

```tsx
// tab-views.tsx 核心
return tabs.map((t) => (
  <Activity key={t.key} mode={t.key === pathname ? "visible" : "hidden"}>
    <Fragment key={t.refreshKey}>
      <TabPage path={t.key === pathname ? pathname + search : t.path} />
    </Fragment>
  </Activity>
))

function TabPage({ path }: { path: string }) {
  return useRoutes(pageRoutes, path) // 页面里的 useLocation / useSearchParams 读到的是这个地址
}
```

- `<Activity mode="hidden">` 隐藏页面但保留 React 状态，并清理它的副作用（不会在后台继续请求、轮询）。不需要引入 react-activation 之类的第三方 keep-alive 库。
- `useRoutes(routes, location)` 让每个页签按自己的地址渲染，所以筛选参数写在地址里的页面切回来时参数也对。
- "刷新"就是改 `refreshKey` 让页面重新挂载，再让活跃查询重新请求。

## 已踩过的坑

1. **隐藏页签的 DOM 还在页面里。** 状态保留的代价是：几个页面同时存在于 DOM 中，只是隐藏了。因此：
   - 页面代码里不要用 `document.querySelector` 之类的全局查询，用 `ref`；
   - 不同页面之间不要出现相同的 `id`；
   - 自动化测试的选择器要加 `:visible`（实测：等待 `table tbody tr` 会先匹配到隐藏的仪表盘表格而一直超时）。
2. **侧边栏和页签里有同样地址的链接。** `a[href="/orders"]` 会同时匹配两处，选择器要限定在侧边栏（`[data-slot="sidebar-content"]`）或页签栏（`[aria-label="已打开的页面"]`）里。
3. **× 按钮不能放进页签的链接里。** 交互元素不能嵌套；页签是一个容器，里面并排放链接和关闭按钮。
4. **页签栏横向滚动要同时写 `overflow-y-hidden`**，否则会冒出纵向滚动条（见 `patterns.md`）。
5. **"关闭其他/左侧/右侧"跳错页签。** 右键的不是当前页签、而当前页签被关掉时，应该跳到右键的那个页签，而不是相邻页签。
6. **首帧空白。** 页签由路由变化写入，首次渲染时当前地址还不在页签里；`TabViews` 会把当前地址临时补进列表渲染，避免闪一下空白。

## 交付检查

下面 25 项在参考实现上已全部实测通过：

- 初始只有固定的"仪表盘"；依次打开 4 个页面后有 5 个页签、顺序正确；当前页签高亮；页签栏没有纵向滚动条
- 切走再切回：地址里的筛选条件还在；勾选的行还在
- "刷新"后勾选清空、筛选保留；浏览器刷新后页签仍在
- 固定页签：右键"关闭"不可用；没有 ×
- 关闭左侧 / 关闭右侧 / 关闭其他：结果正确，当前页被关掉时跳到右键的页签；从菜单再打开的页签加在最后
- 点 × 关闭当前页签跳到右边；中键关闭非当前页签、当前页不变；⌄ → 关闭全部只剩首页并跳回首页
- 不存在的地址显示 404 且不新增页签
- 页签满 10 个后再打开：淘汰最左的可关闭页签，首页保留，新页签在最后；连续打开时继续淘汰最左的（预置页签到 sessionStorage 实测）
- 手机端不显示页签栏，页面正常显示
- 控制台没有运行时错误
